# Практичне заняття № 0. Підготовка робочого середовища розробника

**Дисципліна:** Алгоритмізація та основи програмування

## Тема заняття

Підготовка робочого середовища розробника мовою Java: облікові записи GitHub,
LeetCode, HackerRank; встановлення та налаштування Git, SSH-ключа, Oracle
JDK 25 і IntelliJ IDEA.

**Тип заняття:** підготовче, самостійне.

**Тривалість:** самостійна робота, час не нормується — кожен працює у власному
темпі. Результат має бути отриманий до початку практичного заняття № 1.

**Форма контролю:** захист звіту зі знімками екрана, перевірка облікових
записів, готовність працювати з установленим середовищем на першому
практичному занятті.

## Мета

Сформувати на персональному комп'ютері студента повнофункціональне середовище
розробки мовою Java та зареєструвати облікові записи на платформах, які
використовуються протягом семестру для виконання, здавання й автоматичної
перевірки завдань.

Заняття не містить програмування як такого. Його результат — працездатний
інструментарій. Без виконаного заняття № 0 студент не може приступити до
практичного заняття № 1: усі подальші роботи передбачають наявність
встановлених JDK, IntelliJ IDEA та Git, а також активних облікових записів
GitHub, LeetCode і HackerRank.

## Задачі

Для досягнення мети необхідно розв'язати такі задачі:

1. зареєструвати обліковий запис GitHub, оформити профіль (справжні прізвище
   та ім'я, підтверджена пошта, двофакторна автентифікація) і подати заявку на
   GitHub Student Developer Pack;
2. зареєструвати облікові записи на платформах автоматичної перевірки
   розв'язків — LeetCode і HackerRank — та виконати на кожній із них по одній
   пробній задачі;
3. підготувати робоче середовище термінала: PowerShell 7 і Windows Terminal
   (Windows) або iTerm2 (macOS);
4. встановити систему контролю версій Git і задати параметри `user.name`
   та `user.email`, узгоджені з обліковим записом GitHub;
5. згенерувати пару SSH-ключів, додати відкритий ключ до профілю GitHub і
   перевірити з'єднання, забезпечивши роботу з репозиторієм без введення
   логіна й пароля;
6. встановити Oracle JDK 25, перевірити доступність команд `java` і `javac`
   через змінну середовища `PATH`;
7. встановити IntelliJ IDEA, створити проєкт, підключити до нього JDK 25 та
   скомпілювати і запустити першу програму;
8. зареєструвати облікові записи інструментів штучного інтелекту — ChatGPT і
   Claude — та встановити Claude Code, ознайомившись із правилами їх
   застосування в межах курсу;
9. виконати наскрізну перевірку зв'язності інструментів: створити віддалений
   репозиторій, клонувати його в IDE, зафіксувати зміни та надіслати їх на
   GitHub;
10. оформити звіт про виконану роботу й підготувати перелік ускладнень, що
   виникли, для обговорення на першому практичному занятті.

## Організація та регламент заняття

Заняття — самостійне.

## Очікувані результати

Після виконання роботи студент повинен:

1. мати зареєстрований та підтверджений обліковий запис GitHub;
2. мати зареєстрований обліковий запис LeetCode;
3. мати зареєстрований обліковий запис HackerRank;
4. мати встановлений і працездатний застосунок термінала (PowerShell 7 /
   Windows Terminal, iTerm2 або системний термінал Linux);
5. мати встановлену систему контролю версій Git із налаштованими
   параметрами `user.name` і `user.email`;
6. мати згенеровану пару SSH-ключів, відкритий ключ якої додано до облікового
   запису GitHub, і вміти надсилати зміни без введення логіна та пароля;
7. мати встановлений Oracle JDK 25 та коректно налаштовані змінні середовища;
8. мати встановлену інтегровану середу розробки IntelliJ IDEA, у якій
   створено, скомпільовано й запущено перший проєкт;
9. мати доступ до інструментів штучного інтелекту (ChatGPT, Claude Code) і
   розуміти межі їх припустимого використання під час виконання завдань курсу;
10. уміти перевірити працездатність кожного компонента засобами командного рядка.

## Матеріально-технічне забезпечення

- персональний комп'ютер під керуванням Windows 10/11, macOS 12+ або Linux;
- оперативна пам'ять: мінімум 8 ГБ, бажано 16 ГБ, комфортно 32 ГБ (IntelliJ
  IDEA разом із запущеною JVM і браузером на 8 ГБ працює, але впритул);
- не менше 8 ГБ вільного місця на диску;
- стабільне підключення до мережі Інтернет;
- діюча електронна поштова скринька (рекомендовано — не університетська,
  оскільки доступ до неї зберігається після завершення навчання);
- права адміністратора для встановлення програмного забезпечення.

## Терміни та поняття

| Термін | Пояснення |
|---|---|
| **JDK** (Java Development Kit) | Комплект розробника: компілятор `javac`, віртуальна машина `java`, стандартна бібліотека класів. Без JDK вихідний код мовою Java неможливо перетворити на програму, що виконується. |
| **LTS** (Long-Term Support) | Версія з тривалою підтримкою. JDK 25 — поточна LTS-версія, саме вона використовується в курсі. |
| **IDE** (Integrated Development Environment) | Інтегроване середовище розробки: редактор коду, компілятор, налагоджувач та засоби навігації в одній програмі. |
| **Git** | Розподілена система контролю версій; зберігає історію змін у файлах проєкту. |
| **Репозиторій** | Каталог проєкту разом з усією історією його змін, яку веде Git. |
| **Коміт** (commit) | Зафіксований у історії стан проєкту з текстовим коментарем. |
| **GitHub** | Хмарний сервіс зберігання Git-репозиторіїв; використовується для здавання робіт. |
| **Змінна середовища** | Іменоване значення операційної системи; зокрема `PATH` визначає, де ОС шукає програми, які запускаються за іменем. |
| **SSH** (Secure Shell) | Протокол захищеного зв'язку між комп'ютером і віддаленим сервером. Git використовує його для обміну даними з GitHub. |
| **Пара ключів** | Два пов'язані файли: **закритий** (private) ключ зберігається лише на вашому комп'ютері й нікому не передається, **відкритий** (public) ключ передається на сервер. Сервер упізнає власника закритого ключа, не отримуючи його самого. |
| **Термінал** (командний рядок) | Програма для введення текстових команд і перегляду їх виведення. У Windows — PowerShell 7 або Git Bash, у macOS — Terminal.app чи iTerm2, у Linux — системний термінал. |
| **Оболонка** (shell) | Інтерпретатор команд, що працює всередині термінала: `pwsh` (PowerShell), `bash`, `zsh`. Синтаксис команд залежить саме від оболонки, а не від вікна термінала. |
| **LLM** (Large Language Model) | Велика мовна модель — програма, здатна породжувати текст і код за запитом природною мовою. На ній ґрунтуються ChatGPT і Claude. |
| **CLI-асистент** | Помічник, що працює в командному рядку в каталозі проєкту, має доступ до файлів і може читати та змінювати код (Claude Code). |
| **Парольна фраза** (passphrase) | Пароль, яким шифрується файл закритого ключа на диску. Захищає ключ у разі втрати комп'ютера. |

## Хід роботи

Кроки виконуються **строго послідовно**. Кожен крок завершується перевіркою;
не переходьте до наступного, доки поточна перевірка не дала очікуваного
результату.

### Крок 1. Реєстрація облікового запису GitHub

1. Відкрийте у браузері https://github.com/ та оберіть **Sign up**.
2. Введіть адресу електронної пошти, пароль і **ім'я користувача**
   (username). Ім'я користувача стає частиною публічної адреси вашого
   профілю (`https://github.com/ваше-ім'я`), тому оберіть його свідомо:
   бажано у форматі `прізвище-ініціали` або `ім'я-прізвище` латиницею, без
   жаргонізмів. Змінювати його згодом небажано — усі раніше надані
   посилання стануть недійсними.
3. Підтвердьте адресу пошти за посиланням із листа, що надійде від GitHub.
4. Увімкніть двофакторну автентифікацію (Settings → Password and
   authentication → Two-factor authentication). З 2023 року GitHub вимагає її
   для облікових записів, що публікують код; налаштувати її одразу простіше,
   ніж під час здавання роботи.
5. Заповніть профіль: справжні прізвище та ім'я в полі *Name*. Викладач
   ідентифікує роботи саме за цим полем.
6. **Окремо** подайте заявку на GitHub Student Developer Pack
   (https://education.github.com/pack) з університетською поштою — це надає
   безкоштовний доступ до низки платних інструментів, зокрема до IntelliJ
   IDEA Ultimate. Розгляд заявки триває від кількох годин до кількох діб,
   тому подавайте її на цьому занятті, а не перед дедлайном.

**Перевірка:** сторінка `https://github.com/ваше-ім'я` відкривається у режимі
анонімного перегляду (приватне вікно браузера) і містить ваші прізвище та ім'я.

### Крок 2. Реєстрація на LeetCode

1. Відкрийте https://leetcode.com/ та оберіть **Sign up**.
2. Зареєструйтеся через кнопку **Sign up with GitHub** — це пов'язує обидва
   облікові записи та позбавляє потреби запам'ятовувати окремий пароль.
3. Підтвердьте адресу пошти.
4. У налаштуваннях профілю (Settings → Basic Info) вкажіть прізвище та ім'я.
5. У налаштуваннях редактора (кнопка з шестернею на сторінці будь-якої задачі)
   встановіть мову за замовчуванням **Java**.
6. Відкрийте задачу https://leetcode.com/problems/two-sum/, натисніть **Run**
   із запропонованим шаблоном коду й переконайтеся, що система відповідає
   (очікується повідомлення про помилку компіляції або невірну відповідь —
   це нормально, перевіряється сам факт роботи платформи).

**Перевірка:** у профілі відображається щонайменше одна спроба надсилання.

### Крок 3. Реєстрація на HackerRank

1. Відкрийте https://www.hackerrank.com/ та оберіть **Sign up**.
2. Зареєструйтеся через GitHub або електронну пошту; підтвердьте адресу.
3. У профілі оберіть роль **Student** та вкажіть навчальний заклад.
4. Перейдіть до розділу **Prepare → Java** і виконайте вступну задачу
   *Welcome to Java!* (натисніть **Submit Code** із наданим шаблоном).

**Перевірка:** у розділі Java отримано першу зірку/бал за задачу
*Welcome to Java!*.

### Крок 4. Встановлення термінала

Термінал (командний рядок) — програма, у якій команди вводяться текстом, а не
обираються з меню. Усі подальші перевірки цієї роботи виконуються саме в ньому,
тому середовище слід підготувати до встановлення решти інструментів.

**Windows.** Вбудований `cmd.exe` застарілий і не підтримує частини потрібних
команд. Встановіть **PowerShell 7** і **Windows Terminal**:

- через менеджер пакетів (у наявному вікні PowerShell, запущеному від імені
  адміністратора):

```
winget install --id Microsoft.PowerShell
winget install --id Microsoft.WindowsTerminal
```

- або завантажте інсталятор `PowerShell-7.x.x-win-x64.msi` зі сторінки
  https://github.com/PowerShell/PowerShell/releases, а Windows Terminal —
  з Microsoft Store (https://aka.ms/terminal).

Перевірка: у новому вікні PowerShell 7 виконайте

```
$PSVersionTable.PSVersion
```

У полі *Major* має бути значення **7**, а не 5 (5 — це вбудований
Windows PowerShell, який залишається в системі поряд із новою версією).

> **Зауваження щодо оболонок.** Частина команд цієї методички
> (`ls -al ~/.ssh`, `ssh-keygen`, `eval "$(ssh-agent -s)"`) — команди
> Unix-оболонки. У Windows їх виконують у **Git Bash**, який встановлюється
> разом із Git (крок 5); PowerShell 7 використовується для решти команд.
> Windows Terminal дозволяє відкривати обидві оболонки у вкладках одного вікна.

**macOS.** Вбудований **Terminal.app** працездатний, проте в курсі
використовується **iTerm2** — він зручніший для роботи з кількома сеансами та
для пошуку у виведенні:

1. завантажте архів зі сторінки https://iterm2.com/downloads.html;
2. розпакуйте його подвійним клацанням і перенесіть `iTerm.app` до каталогу
   **Програми** (`/Applications`);
3. запустіть застосунок і підтвердьте запуск, якщо система запитає дозвіл.

Альтернативний спосіб — через менеджер пакетів Homebrew (https://brew.sh/):

```
brew install --cask iterm2
```

Перевірка: iTerm2 запускається, а команда `echo $SHELL` виводить `/bin/zsh`.

**Linux.** Вбудованого термінала дистрибутива (GNOME Terminal, Konsole)
достатньо; додаткових дій не потрібно.

**Перевірка (для всіх ОС).** У вікні термінала виконайте команди `whoami` та
`pwd` — вони мають вивести ім'я користувача та поточний каталог. Надалі під
«терміналом» розуміється PowerShell 7 або Git Bash (Windows), iTerm2 (macOS),
системний термінал (Linux).

### Крок 5. Встановлення Git

**Windows**

1. Завантажте інсталятор із https://git-scm.com/downloads (розділ Windows).
2. Запустіть інсталятор. Усі параметри залишайте за замовчуванням, окрім:
   - *Choosing the default editor used by Git* — оберіть редактор, яким
     ви користуєтесь (наприклад, Notepad++ або Visual Studio Code); не
     залишайте Vim, якщо ви з ним незнайомі;
   - *Adjusting the name of the initial branch* — оберіть
     **Override the default branch name** зі значенням `main`.
3. Після встановлення відкрийте застосунок **Git Bash**.

**macOS**

1. Відкрийте застосунок **Terminal** і виконайте `git --version`.
2. Якщо Git відсутній, система запропонує встановити Command Line Tools —
   погодьтеся; альтернативно скористайтеся інсталятором із git-scm.com.

**Linux (Debian/Ubuntu)**

```
sudo apt update
sudo apt install git
```

**Налаштування (обов'язкове для всіх ОС).** Виконайте у терміналі, підставивши
власні дані. Адреса пошти має збігатися з адресою, вказаною під час реєстрації
на GitHub, інакше коміти не буде пов'язано з вашим профілем:

```
git config --global user.name "Прізвище Ім'я"
git config --global user.email "ваша.пошта@example.com"
git config --global init.defaultBranch main
```

**Перевірка:**

```
git --version
git config --global --list
```

Перша команда має вивести версію (не нижче 2.40), друга — щойно задані
параметри.

**Додатково (за бажанням).** Для роботи без командного рядка встановіть
графічний клієнт GitHub Desktop — https://desktop.github.com/download/ — та
увійдіть у ньому під своїм обліковим записом GitHub. Це не звільняє від
встановлення й налаштування самого Git.

### Крок 5.1. Створення SSH-ключа та прив'язка його до GitHub

GitHub не приймає пароль облікового запису під час надсилання змін
(команда `git push`). Замість введення логіна й пароля використовується пара
криптографічних ключів: закритий зберігається на вашому комп'ютері, відкритий
додається до профілю GitHub. Ключі створюються **один раз**, після чого всі
операції з репозиторієм виконуються без запиту облікових даних.

**1. Перевірте, чи ключ уже існує.** У терміналі (Windows — **Git Bash**, не
`cmd`) виконайте:

```
ls -al ~/.ssh
```

Якщо у виведенні є файли `id_ed25519` та `id_ed25519.pub`, ключ уже створено —
переходьте до пункту 4. Повідомлення `No such file or directory` означає, що
ключів немає, — це нормально для нового комп'ютера.

**2. Згенеруйте пару ключів.** Підставте адресу пошти, вказану під час
реєстрації на GitHub:

```
ssh-keygen -t ed25519 -C "ваша.пошта@example.com"
```

Програма поставить три запитання:

- *Enter file in which to save the key* — натисніть **Enter**, залишивши шлях
  за замовчуванням (`~/.ssh/id_ed25519`);
- *Enter passphrase* — введіть парольну фразу. Її буде запитано лише при
  першому використанні ключа в сеансі роботи; порожня фраза припустима, але
  тоді будь-хто з доступом до вашого комп'ютера зможе діяти від вашого імені;
- *Enter same passphrase again* — повторіть введення.

Символи парольної фрази під час набору **не відображаються** — це не помилка.

У результаті буде створено два файли:

| Файл | Призначення |
|---|---|
| `~/.ssh/id_ed25519` | **закритий** ключ; не передається нікому й ніколи не додається до репозиторію |
| `~/.ssh/id_ed25519.pub` | **відкритий** ключ; саме його додають до GitHub |

**3. Запустіть агент SSH і додайте до нього ключ** (агент зберігає розшифрований
ключ у пам'яті, щоб не вводити парольну фразу під час кожної операції):

```
eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
```

У macOS замість другої команди виконайте
`ssh-add --apple-use-keychain ~/.ssh/id_ed25519`, щоб парольна фраза зберігалася
у зв'язці ключів.

**4. Скопіюйте вміст відкритого ключа:**

```
cat ~/.ssh/id_ed25519.pub
```

Виведений рядок починається з `ssh-ed25519` і закінчується вашою адресою пошти.
Виділіть та скопіюйте його **повністю, одним рядком, без пробілів на початку й
у кінці**. Ніколи не відкривайте й не публікуйте файл без розширення `.pub` —
це закритий ключ.

**5. Додайте ключ до облікового запису GitHub:**

- увійдіть на https://github.com/;
- **Settings** → **SSH and GPG keys** → кнопка **New SSH key**;
- *Title* — довільна назва, що ідентифікує комп'ютер, наприклад
  `Notebook Windows 11` або `PC-audytoriya-305`;
- *Key type* — **Authentication Key**;
- *Key* — вставте скопійований рядок;
- натисніть **Add SSH key** та підтвердьте дію паролем облікового запису.

**6. Перевірте з'єднання:**

```
ssh -T git@github.com
```

Під час першого підключення з'явиться запит
`Are you sure you want to continue connecting (yes/no/[fingerprint])?` —
введіть `yes` (натиснути лише Enter недостатньо). Очікуваний результат:

```
Hi <ваше-ім'я>! You've successfully authenticated, but GitHub does not provide shell access.
```

Друга частина повідомлення — не помилка: GitHub не надає доступу до командної
оболонки, а лише підтверджує автентифікацію. Якщо замість імені виведено
`Permission denied (publickey)`, ключ не додано до профілю або додано вміст не
того файлу.

**7. Використовуйте адресу SSH.** На сторінці репозиторію кнопка **Code**
пропонує дві адреси. Обирайте вкладку **SSH**:

```
git@github.com:username/repository.git      — правильно (без пароля)
https://github.com/username/repository.git  — вимагатиме токен при кожному push
```

Якщо репозиторій уже клоновано через HTTPS, адресу можна змінити без
повторного клонування:

```
git remote set-url origin git@github.com:username/repository.git
git remote -v
```

**Перевірка:** команда `ssh -T git@github.com` виводить рядок
`Hi <ваше-ім'я>!`, а `git remote -v` показує адресу, що починається з
`git@github.com:`.

### Крок 6. Встановлення Oracle JDK 25

1. Відкрийте https://www.oracle.com/java/technologies/downloads/#java25.
2. Оберіть вкладку своєї операційної системи та завантажте інсталятор:
   - Windows — `x64 Installer` (файл `.exe`);
   - macOS — `ARM64 DMG Installer` для процесорів Apple Silicon (M1–M4) або
     `x64 DMG Installer` для Intel-процесорів;
   - Linux — пакет `.deb` або `.rpm` відповідно до дистрибутива.
3. Запустіть інсталятор і пройдіть встановлення з параметрами за
   замовчуванням. Запам'ятайте каталог встановлення, наприклад
   `C:\Program Files\Java\jdk-25`.
4. **Windows: налаштування змінних середовища.** Інсталятор Oracle зазвичай
   робить це самостійно, але результат слід перевірити:
   - «Панель керування» → «Система» → «Додаткові параметри системи» →
     «Змінні середовища»;
   - у системних змінних створіть `JAVA_HOME` зі значенням шляху до каталогу
     JDK (без підкаталогу `bin`);
   - у змінній `Path` додайте запис `%JAVA_HOME%\bin`;
   - закрийте всі відкриті вікна командного рядка та відкрийте нове —
     змінні середовища зчитуються лише під час запуску.

**Перевірка.** У новому вікні командного рядка (Git Bash, PowerShell,
Terminal) виконайте:

```
java -version
javac -version
```

Обидві команди мають вивести версію 25. Якщо `java` працює, а `javac` — ні,
встановлено середовище виконання (JRE), а не комплект розробника (JDK);
повторіть встановлення, завантаживши саме JDK.

### Крок 7. Встановлення IntelliJ IDEA

1. Відкрийте https://www.jetbrains.com/idea/download/.
2. Завантажте **Community Edition** (безкоштовна, її функціональності
   достатньо для всього курсу). За наявності схваленої студентської ліцензії
   (див. крок 1, п. 6) можна встановити Ultimate Edition.
3. Встановіть програму з параметрами за замовчуванням. У Windows у діалозі
   встановлення доцільно позначити *Add "bin" folder to the PATH* і
   *Create Desktop Shortcut*.
4. Під час першого запуску прийміть умови ліцензії та оберіть колірну схему.
5. Створіть перший проєкт: **New Project** → тип **Java** →
   у полі *JDK* оберіть встановлений JDK 25 (якщо його немає у списку —
   *Add JDK* і вкажіть каталог із кроку 5) → увімкніть прапорець
   *Add sample code* → *Create*.
6. У створеному файлі `Main.java` натисніть зелений трикутник ліворуч від
   методу `main` і виберіть *Run 'Main.main()'*.

**Перевірка:** у нижній панелі *Run* виведено текст `Hello, World!` та рядок
`Process finished with exit code 0`.

### Крок 8. Реєстрація в ChatGPT

1. Відкрийте https://chatgpt.com/ та оберіть **Sign up**.
2. Зареєструйтеся через обліковий запис Google, Microsoft, Apple або за

   підписки не є обов'язковим.
4. Перевірте роботу сервісу навчальним запитом, наприклад:

### Крок 9. Реєстрація Claude та встановлення Claude Code

Claude Code — асистент, що працює в командному рядку безпосередньо в каталозі
проєкту: на відміну від діалогу в браузері, він бачить файли проєкту, може
пояснювати наявний код і вносити до нього зміни.

1. **Обліковий запис.** Відкрийте https://claude.ai/ та зареєструйтеся
   (Google або електронна пошта); підтвердьте адресу.
2. **Умови доступу.** Для роботи в браузері достатньо безкоштовного тарифу.
   Claude Code потребує платної підписки або оплачених API-кредитів; чинні
   умови перевіряйте на сторінці https://www.claude.com/pricing.
   Оформлення підписки **не є обов'язковою умовою** складання курсу — за її
   відсутності обмежтеся кроком 8 і веб-версією Claude, зазначивши це у звіті.
3. **Node.js.** Claude Code потребує середовища Node.js версії 18 або новішої.
   Завантажте LTS-версію з https://nodejs.org/ і встановіть із параметрами за
   замовчуванням. Перевірка: `node --version`.
4. **Встановлення:**

```
npm install -g @anthropic-ai/claude-code
```

5. **Перший запуск.** У терміналі перейдіть до каталогу проєкту та запустіть
   асистента:

```
cd /шлях/до/aop-practice-0
claude
```

   Під час першого запуску відкриється браузер із запитом на вхід до
   облікового запису Claude. Після авторизації поверніться до терміналу.
6. Поставте перевірочний запит українською, наприклад:
   `Поясни, що робить файл README.md у цьому каталозі`.
   Завершення сеансу — команда `/exit`.

**Перевірка:** команда `claude --version` виводить номер версії; асистент
відповідає на запит у каталозі проєкту.

**Правила використання інструментів ШІ в межах курсу.** ChatGPT і Claude Code
дозволено застосовувати для пояснення повідомлень про помилки, незнайомих
термінів і методів стандартної бібліотеки, а також для перевірки власного
розв'язку. Здавання згенерованого коду, якого студент не може пояснити,
розцінюється як порушення академічної доброчесності: під час захисту роботи
викладач має право поставити запитання щодо будь-якого рядка поданого коду, і
відповідальність за нього несе автор роботи, а не інструмент.

## Типові помилки та способи їх усунення

1. **`'java' is not recognized as an internal or external command`** —
   каталог `bin` комплекту JDK відсутній у змінній `PATH`, або вікно
   командного рядка відкрито до зміни змінних середовища. Перевірте `PATH`
   і відкрийте нове вікно.
2. **`java -version` показує версію 8 або 17** — на комп'ютері встановлено
   кілька версій Java, і в `PATH` першою стоїть стара. Видаліть застарілу
   версію або перемістіть запис `%JAVA_HOME%\bin` на початок `PATH`.
3. **`javac` не знайдено при робочому `java`** — встановлено JRE замість JDK.
4. **IntelliJ IDEA не бачить JDK** — у діалозі *Project Structure → SDKs*
   додайте JDK вручну, вказавши каталог встановлення.
5. **Коміти на GitHub не пов'язані з профілем** — значення `user.email` у Git
   не збігається з жодною адресою, підтвердженою в обліковому записі GitHub.
6. **`Permission denied (publickey)`** — відкритий ключ не додано до профілю
   GitHub або скопійовано вміст не того файлу. Повторіть кроки 5.1.4–5.1.5,
   копіюючи саме `id_ed25519.pub`.
7. **`Support for password authentication was removed`** — репозиторій клоновано
   через HTTPS. Змініть адресу командою
   `git remote set-url origin git@github.com:username/repository.git`.
8. **Парольну фразу запитують під час кожної операції** — ключ не додано до
   агента SSH. Виконайте `eval "$(ssh-agent -s)"` та
   `ssh-add ~/.ssh/id_ed25519`; у Windows це слід повторювати після
   перезавантаження, якщо не увімкнено службу *OpenSSH Authentication Agent*.
9. **`ssh-keygen: command not found` у Windows** — команду виконано в `cmd` або
   PowerShell без OpenSSH. Використовуйте **Git Bash**.
10. **`winget` не розпізнається як команда** — застаріла версія Windows або
    відсутній *App Installer*. Встановіть його з Microsoft Store або
    скористайтеся завантаженням інсталятора `.msi` вручну.
11. **Команди `ls`, `ssh-keygen`, `eval` не працюють у PowerShell** — це команди
    Unix-оболонки. Виконуйте їх у **Git Bash**.
12. **`npm: command not found`** — не встановлено Node.js або відкрито вікно
    терміналу до його встановлення. Перевірте `node --version` у новому вікні.
13. **`claude` не запускається після встановлення** — глобальний каталог
    пакетів npm відсутній у `PATH`. Визначте його командою
    `npm config get prefix` і додайте підкаталог `bin` (у Windows — сам
    каталог) до змінної `PATH`.
14. **Кирилиця в шляху до проєкту** — уникайте каталогів на кшталт
   `C:\Users\Іван\Документи`; окремі інструменти працюють із такими шляхами
   некоректно. Розміщуйте проєкти в каталозі без пробілів і кирилиці,
   наприклад `C:\dev\aop`.
